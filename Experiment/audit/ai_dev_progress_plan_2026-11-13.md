## 2. 开发模式：AI 自主开发

### 2.1 角色分工

| 角色 | 职责 |
|---|---|
| 人（用户） | 给方向（一句「继续」「检查进度」「提交 git」）、提出质疑、验收结果、决定优先级 |
| AI（本会话） | 读判据与历史证据链 → 设计并实现独立实验台 → 跑 10 seed 配对消融 → 生成报告 → 同步判据/进度报告/大纲附录/工作日志 → 构建与哈希核验 → Git 提交/推送 |

三轮 T1 实验（v1.6 / v1.7 / v1.8）各自都由用户一句「继续」触发，
AI 独立完成全部实现与收尾，无人工编码介入。

### 2.2 每一轮的固定交付物（不可裁剪）

1. 独立 C 实验台 + DLL（只链接既有 `b1_core.o` / `seed_bundle.o`，核心源码零改动）
2. Python 驱动脚本（10 seed / 300 试次，`--quick` 冒烟 + `--report-only` 重算）
3. 可复算 JSONL 数据（本轮 184 条）并加入 `.gitignore`
4. `audit/` 实验报告，含 SHA1 证据链
5. `spec/judgments.md` 追加现状复核章节 + 版本记录（**阈值零变更**）
6. 进度报告 §9.x（MD + HTML，同步章节断言与 P0 文案）
7. 桌面大纲原件与 `audit/` 副本追加附录，两份 SHA1 校验一致
8. `.workbuddy/memory/` 工作日志、`build.ps1` 编译/备份/哈希清单、最终 `-Backup -Smoke` + 报告哈希刷新 + lint + Git 提交

### 2.3 实测速率 vs 大纲人力估算

| 口径 | 数值 | 来源 |
|---|---|---|
| 大纲 §5.3 总工期 | ≈ 40 周 + 20% 缓冲 ≈ **48 周**（全职单人）；兼职 15 h/周 ≈ **2.5 年** | 大纲 v1.0，人力工时假设 |
| AI 实测：M0 + M1 主体 | 2026-11-12 19:23 → 23:35，约 **4 小时** | `git log` |
| AI 实测：单轮 T1 实验 | v1.6→v1.7 **23 分钟**；v1.7→v1.8 **1 小时 57 分** | `git log` |
| 单轮产出量 | 约 600 行 C + 700 行 Python + 184–257 条数据 + 报告 + 5 处文档同步 + 构建 + 提交 | 本轮 `git diff --stat`：1884 增 |

**结论**：工程实现环节的 AI 速率比人力估算高 1–2 个数量级，
因此**日历日期不能再按「周」排**，应按「会话轮次」排。

**但严禁线性外推**：T1 是开放性机制研究，不是纯编码任务。
v1.4→v1.8 连续五轮均为负结果或局部结果，B1 至今未过。
「代码交付速率」不等于「研究突破速率」，下面的日期只承诺**执行与验证**，
**不承诺通过判据**。

### 2.4 不可省略的纪律（AI 每轮自检）

- 判据阈值零变更；不调 `lr / psp / τ`、不改刺激生成器、不挑最好一组刷分
- 能力口径严格 `g=0`；冻结投票；评估前后权重漂移必须为 0；同时报告 A/B 预测分布差
- 同 seed 配对消融归因「完整 − 无迹 ≥30pp」；四流单变量覆盖
- 诊断组 / 作弊对照 / 扫描组零星提升一律不计入验收
- 核心 `benchmark1_core.c` SHA1 恒定；构建哈希、报告 SHA1、数据 JSONL 相互可核
- `judgments.md:4`：**未通过 B1 之前，不得启动 B2 以上开发** → 不进 B2、不写容器、不写 SNC
