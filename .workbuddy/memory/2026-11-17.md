## neuron_vis.py v5.1 渲染优化（大网络卡顿修复）

**问题**：神经元规模增大（2200 / 4400）后窗口动画明显卡顿。

**诊断**（基准脚本实测 4400 节点 offscreen）：
- `update_snapshot` 纯 numpy 逻辑只要 1ms，不是瓶颈
- `update+repaint` 要 **55ms/帧（18 FPS）**，瓶颈在 Qt 逐个渲染 4400 个 `QGraphicsEllipseItem`
- 分解 repaint：高亮突触线 QPainterPath（450 条 AA 线）**34.7ms** 是最大头，
  脉冲光晕 path 5.5ms，节点图元其余；关全局 AA 能到 25ms 但画质损失

**修复**：把 N 个节点图元 + 3 条动态 QPainterPath 全部合并成**单张 numpy 光栅化位图**
（`QGraphicsPixmapItem`）：
- `NetworkGraph._build_node_raster()`：预生成节点圆点模板 `(256,M,4)`、光晕模板、
  展平像素索引 `_flat`（N×M），一次建好 `QImage`/`QPixmap`
- `_draw_nodes(idx, cur_idx, ghost_idx, chosen)`：每帧清空 buffer，numpy scatter 依次写
  高亮线 → 残影光晕 → 当前光晕 → 节点圆点，`convertFromImage` 一次上传
- `_draw_lines()`：高亮突触用等距采样点 numpy 写，采样间隔 6px，上限 300 条
- 光晕/高亮限流 `_limit_idx(cap=700)`，均匀分布抽样
- `active_item`/`spike_cur`/`spike_ghost` 保留为空壳对象但 `setVisible(False)`，兼容旧引用

**两个踩坑（关键）**：
1. **QGraphicsPixmapItem 持有 pixmap 副本**：每帧 `convertFromImage` 后必须
   `self._node_item.setPixmap(self._node_pix)`，否则节点不显示（截图验证过：
   不调用时截图只有层标签、无节点，25KB；调用后 780KB 正常）
2. **小端 QImage(Format_ARGB32) 内存序是 BGRA**：numpy buffer 写模板时通道要按
   B,G,R,A 排（`tmpl[:,:,0]=LUT[:,2]`），否则颜色错乱

**效果**：4400 节点 `update+repaint` 从 55ms → **17.7ms/帧（约 56 FPS）**，提升约 3 倍。
截图验证：节点渐变色、光晕、高亮线、层标签均正常；主程序 `MainWindow` 启动无报错。

**备份**：`vis/neuron_vis_优化前备份_20261117.py.bak`（103KB 原版）。

**可调参数**：光晕 cap 700（`_limit_idx` 调用处）、高亮线上限 300（`chosen[:300]`）、
线采样间隔 6px（`_draw_lines` 的 `steps`）。想再快可降这些；想画质更好调高。
